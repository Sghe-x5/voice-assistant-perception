# Кодбук наблюдений: версия 0.1 для пилота

**Предложенная схема, ещё не проверенная на корпусе.** Никакие примеры ниже не являются реальными наблюдениями. Единица: эпизод достижения одной цели, содержащий запрос, ответ и при необходимости уточнение/исправление до завершения, смены цели или отказа. Дополнительно выделяется ход. Один разговор может содержать несколько связанных эпизодов; сохранять session_id и participant_id для зависимости наблюдений.

## Поля эпизода

| Поле | Значения / правило |
|---|---|
| evidence_origin | human_human_recorded / human_assistant_recorded / retrospective_report / agent_run / scripted_stimulus. Не смешивать |
| context_access | Что было доступно человеку и системе перед решением: история, экран, память, инструменты. Не предполагать доступ |
| task_family | fact / state_action / constrained_planning / explanation / creative / social / mixed / unknown |
| information_state | sufficient / missing_parameter / ambiguous_reference / conflicting_constraints / unknown. Можно несколько меток |
| information_evidence | Номер хода и дословный минимальный фрагмент, подтверждающий наличие или отсутствие параметра в доступном контексте |
| assistant_action | answer / act / targeted_question / broad_repeat / explicit_assumption / acknowledge_error / revise / refuse / other. Можно несколько |
| repair_initiator | user / assistant / both / none / unknown |
| repair_target | recognition / reference / intent / constraint / factual_error / tool_state / turn_taking / unknown |
| repair_outcome | resolved / partial / unresolved / abandoned / not_applicable / unknown; подтверждение состоянием задачи |
| objective_result | success / partial / failure / unscorable / unknown; отдельная версия рубрики |
| user_effort | Дополнительные ходы, слова, активное время речи, повторённые ограничения; неизвестное = null |
| subjective_rating | Только прямая оценка участника, время измерения и версия пункта; не выводить из тона или текста |
| provenance | pseudonymous source/session/episode/turn IDs, версия модели, режим, дата, coder_id, codebook_version |

## Как отличать полезное уточнение от повторного запроса

1. Назвать параметр, необходимый для выбранной задачи. Нужен эталон или явное требование; личное предпочтение разметчика недостаточно.
2. Проверить контекст, реально доступный ассистенту до вопроса. Информация в голове человека не считается сообщённой системе.
3. Проверить, меняет ли возможный ответ выбор допустимого действия. Если неясно — `unknown`, а не «бесполезное».
4. `new_information_request`: параметр нужен и ещё не сообщён. `repeat_known_information`: параметр уже дан и не изменён. `confirmation`: система проверяет понятое значение; не приравнивать подтверждение автоматически к повторному запросу.
5. Если был шум/ошибка ASR, сохранить две метки: информация присутствует в пользовательской речи, но отсутствует/искажена в распознанном контексте. Это не доказанная ошибка reasoning-модели.

Иллюстрация: «На десять минут» присутствует в аудио, но ASR записал «на две минуты». Последующее уточнение может быть обоснованным относительно распознанного контекста. Не наказывать языковую модель за недоступную ей информацию.

## Как считать нагрузку

- `extra_user_turns`: ходы сверх минимально достаточной последовательности по заранее заданному эталону; если эталон спорен, сохранять только общее число и `unknown` для excess.
- `repeated_constraints`: сколько ранее доступных и неизменённых ограничений пришлось сообщить повторно. Сохранять ссылки на оба хода. Не считать любое повторение слова потерей контекста.
- `active_user_seconds`: суммарная длительность речи пользователя, отдельно от ожидания.
- `repair_elapsed_seconds`: от обнаруженного запуска исправления до подтверждённого завершения; незавершённый эпизод — цензурированный/незавершённый, не ноль.
- Не вводить веса вида «вопрос = 3 балла, секунда = 1 балл» без обоснования. Сначала отдельные показатели, затем проверка дополнительной прогностической информации.

## Временные события

Каждое событие: session_id, trial_id, turn_id, event_type, monotonic_ms, clock_id, collector_version. Отдельно UTC-дата сессии. Нельзя вычитать отметки разных часов без синхронизации.

Минимум: user_speech_start/end, asr_final, request_sent, first_token, first_audio, first_substantive_audio, audio_end, interruption, task_state_changed, rating_shown, rating_submitted. Если TTS издаёт «угу» до содержательного ответа, first_audio и first_substantive_audio различаются.

`first_audio - user_speech_end` = задержка до начала звука; `first_token - request_sent` = API TTFT; `audio_end - user_speech_start` = длительность конкретного обмена. Это разные величины. Первые две не включают одинаковые части системы. Неполная запись не восстанавливается «типичным временем».

## Разметка и качество

Сначала совместно разобрать несколько тренировочных эпизодов. Затем независимо размечать новые, не видя субъективных оценок и по возможности бренда. Сохранить исходные метки до согласования. Для номинальных классов — agreement, матрица путаницы и Cohen kappa / Krippendorff alpha при соответствующем дизайне; для порядковых — подходящая взвешенная мера. Для количественных длительностей — ошибки/разницы и согласованность измерений. Указать распространённость классов и неопределённость, не вводить магический проходной порог.

Версии кодбука хранить; изменение определения требует повторной разметки затронутых записей. Автоматическая разметка — отдельный предиктор с проверкой на человеческой разметке. Согласие двух LLM не является межэкспертной надёжностью двух людей.

До начала основного сбора определить хранение записей, срок удаления, доступ исследовательниц и правила публикации. В репозиторий входят кодбук и разрешённые агрегаты; аудио и индивидуальные экспорты туда автоматически не попадают.
