# Совместная работа

## Первый вход

1. Примите приглашение в GitHub под своим аккаунтом. Пока оно не принято,
   приватный репозиторий может показывать 404.
2. Клонируйте репозиторий и выполните установку из README.
3. Прочитайте AGENTS.md, docs/research_plan_ru.md и research/verification.md.

Роль **Write** позволяет читать репозиторий, создавать ветки, отправлять коммиты,
редактировать файлы и работать с PR. Для этих задач роль Admin не нужна.

## Одна задача — одна рабочая ветка

```bash
git switch main
git pull --ff-only
git switch -c codex/short-task-name
```

Замените `short-task-name` коротким названием своей задачи. Не переключайте ветки
поверх чужих незакоммиченных изменений. Если два агента работают параллельно,
разделите файлы и ответственность до редактирования.

Перед отправкой проверьте изменённые функции, связанные результаты и список файлов.

```bash
git diff --check
git status --short
```

Добавляйте явно выбранные файлы; не включайте локальные данные. В PR кратко укажите
проблему, изменение, проверки и научные ограничения. После CI и ревью объединяйте
результат. Основная ветка должна оставаться воспроизводимой.

## Где менять

- Методы и выводы: research/, analysis/, src/ и results/.
- Документация и план: docs/, README.md, AGENTS.md.
- Формы, сценарии и разметка: pilot/; реальные JSON-экспорты хранить вне Git.
- Промежуточные результаты: results/README.md со ссылками на расчёты и ограничения.

Новые данные не подменяют старые: сохраняйте источник, лицензию, единицу наблюдения
и правила включения. Не называйте ответы нейросети человеческими наблюдениями.
