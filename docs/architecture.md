# Как устроен проект

## Основной расчёт

Манифест источников → загрузка и проверка хешей → локальные исходные данные →
три отдельных анализа → прогнозы и агрегированные таблицы → статья.

- `src/analyze_voice.py` — оценки голосовых видеосценариев.
- `src/analyze_cocreation.py` — текстовая совместная работа с ИИ.
- `src/analyze_latency.py` — текстовый эксперимент с задержками.
- `src/compare_information.py` — сравнение наборов признаков на тех же людях.
- `src/bootstrap_voice_training.py` — повторное обучение для оценки устойчивости.
- `src/predict_voice.py` — применение сохранённой исследовательской модели.

`scripts/run_all.py` выполняет шаги в нужном порядке. Статус текущего запуска
и ошибки сохраняются локально в `results/reproduction.json`.
`analysis/validation/` содержит независимые численные проверки;
`analysis/lexical/` — дополнительный текстовый baseline.

## Данные и результаты

В Git находятся только происхождение источников, манифест, код, выбранные
агрегированные таблицы и статья. Исходные анкеты, индивидуальные прогнозы,
bootstrap-выборки и рабочие логи создаются локально и игнорируются Git.
Разные исследования не объединяются в одну якобы общую шкалу.

## Новый пилот

Локальная форма → JSON, экспортированный человеком → строгая проверка →
описательный отчёт. Этот поток отделён от опубликованных исследований.
Агентные ответы не превращаются в человеческие оценки; наблюдения одного
человека не считаются независимыми участниками.

## Естественные диалоги

`pilot/fieldwork.py`: отдельная схема дневника → проверка происхождения и
разрешения на анализ → два одинаковых пакета без бренда и оценок → независимая
ручная разметка → описательный отчёт согласия. Используются строгие JSON helpers
из существующего анализатора. Сессии исследовательниц, добровольцев, рассказы по
памяти и разные модальности не объединяются в одну группу. Пакеты остаются
локальными; программа не гарантирует анонимность текста и не вызывает модели.

Версия diary-1.1 хранит упорядоченные ходы, вопросы о конкретных параметрах и
подтверждённый вход до вопроса. `question_coding.py` проверяет этот контракт внутри
прежнего prepare/compare пути. Пользовательская речь и вход ассистента — разные
каналы доказательств. coding-1.1/codebook-0.2 сохраняет знакомство разметчика с эпизодом и разделение
на материал для разработки и проверки правил. Старые записи читаются отдельно.

## Сценарный пилот

`pilot/process_transfer/materials.py` задаёт сценарии; `study.py` формирует план
и HTML-страницы на основе `form.html`. Участник скачивает ответы в JSON. При
импорте `study.py` проверяет файл по исходному плану, а `summaries.py` вычисляет
различия прогнозов и границы при пропусках. `diagnostics.py` отдельно считает
математические контрпримеры для интерпретации этих различий.
