# Пилот: что человек выводит из процесса решения

**Готов инструмент проверки процедуры, не новое исследование на людях.**
Это текстовые вымышленные сценарии; никакие модели или голосовые сервисы не
вызываются. Авторство вычисления задано в сценарии, а не установлено по скрытому
рассуждению LLM. Участник — наблюдатель, не пользователь живого ассистента.

Развитие кандидата из [PR №3, ревизия 1510fe4](https://github.com/Sghe-x5/voice-assistant-perception/blob/1510fe4d0b3b20f0e64fbcb6e7368d94b3bceb38/research/experiment_design_2026-11-05.md).
Модуль независим от ещё не слитого PR: существующие данные и статья не меняются.

## Что подготовлено

- Два способа получить **одинаковый правильный итог**: вычисление ассистентом
  либо готовая поправка от отдельного модуля. Весь арифметический текст одинаков.
- Полный квадрат проверочных задач: та же/другая тема × та же/другая операция.
- Две темы (расписание/запасы), по два числовых варианта; это ограниченный набор
  экземпляров, **не четыре независимых семейства задач**.
- Отдельные оценки умности, симпатии, полезности и трудности чтения; прогнозы
  успешности, вопросы понимания, пропуски и досрочное завершение.
- Офлайн-страницы, строгий импорт, описательный анализ с отдельными группами
  авторской отладки, добровольцев и синтетических проверок.
- [Протокол и конкурирующие объяснения](PROTOCOL.md), [задание на ревью](REVIEW.md).

## Подготовка и прохождение

Python 3.12, только стандартная библиотека. Из корня проекта:

```bash
.venv/bin/python pilot/process_transfer/study.py build \
  --seed 20261105 --batch-id author-debug-01 --output pilot/local-process-debug \
  --role developer_pilot --origin human_observer \
  --study-info 'Авторская проверка процедуры. Файл остаётся у вас; его можно удалить или не передавать. Внешние участники этим запуском не набираются.'
```

Получатся `plan.json`, инструкция распределения и 64 самостоятельные HTML-страницы.
**64 — размер полного блока распределения, не рекомендуемый N и не число уже
существующих участников.** В маленьком пилоте весь блок проходить не обязательно;
незавершённый блок может быть несбалансированным. План не даёт права заявлять мощность.

1. Исследовательница выдаёт следующую неиспользованную страницу `S001.html` и
   случайный код вида `P-0123456789ab`. Соответствие человека/кода/слота хранится
   отдельно. Один человек проходит один слот; прерванный слот не переиспользуется.
2. Участник открывает HTML в браузере, читает условия, даёт согласие и отвечает.
   Не показывайте ему `plan.json`, исходники, другие условия или гипотезу заранее.
   Знающий гипотезу автор остаётся в `developer_pilot`.
3. По завершении или досрочной остановке сохраняется локальный JSON. Передачи
   через сеть нет; обновление вкладки теряет ответы. Не заполнять форму за человека.
4. Для внешнего пилота создайте **новую папку** с `--role volunteer`, реальным
   контактом исследовательницы, правилами передачи/хранения, сроком удаления и
   отзывом согласия в `--study-info`. Эти решения не установлены данным модулем.
   Не используйте тестовую надпись вместо согласованной инструкции.

Для технического тестирования используйте `--origin synthetic_test`: видимая
плашка и экспорт сохранят происхождение. Не менять его на человеческое после
автоматического прохождения. Проверки идентификаторов/согласия — декларации,
не подтверждение личности или независимости наблюдения.

## Анализ настоящих экспортов

```bash
.venv/bin/python pilot/process_transfer/study.py analyze \
  --plan pilot/local-process-debug/plan.json \
  --exports /absolute/private/path/S001-P-0123456789ab.json \
  --output pilot/local-process-report.json
```

Каждому отдельному набору выдавайте новый `--batch-id`; не переиспользуйте слот
или идентификатор набора. Роль, происхождение и инструкция согласия входят в хеш
плана и не могут быть заменены в экспорте без ошибки проверки.

Используйте план именно той версии, которой проходил участник. Хеши связывают
стимулы, распределение, генератор и форму; изменение инструмента требует нового
набора и сохранения старого кода для чтения старых экспортов. Миграция версий
пока не реализована. Не редактируйте вручную хеши ради совместимости.

Анализ не перезаписывает существующие отчёты, отклоняет дубли людей/слотов,
неправильный план, нецелые оценки, ответы с непоказанных страниц. Пропуски остаются
`null`; неверное понимание не служит автоматическим исключением. Разные порядки
анкеты/прогнозов разделены. Вывод содержит знаменатели, крайние ответы, покрытие
экземпляров и описательный контраст; p-value/CI и популяционные выводы отсутствуют.
Без экспортов человеческих результатов нет. Тексты, планы распределения, ответы
и отчёты остаются локальными и игнорируются Git; исходные **авторские** стимулы
и тесты входят в репозиторий.

## Проверки

```bash
.venv/bin/python -m unittest discover -s tests -p test_process_transfer.py -v
.venv/bin/python pilot/process_transfer/diagnostics.py
```

Вторая команда печатает **математические контрпримеры**, не оценки людей. В том
числе показывает, как общий сдвиг на log-odds шкале создаёт видимое различие
переноса на шкале процентов. Подробности и границы вывода — в протоколе.

Дополнительный браузерный smoke test (Node.js, установленный Playwright и его
Chromium либо `CHROME_PATH` к отдельному исполняемому Chrome):

```bash
.venv/bin/python pilot/process_transfer/study.py build \
  --seed 20261105 --batch-id ui-check-01 --origin synthetic_test \
  --study-info 'Только синтетическая техническая проверка.' \
  --output pilot/local-process-ui
node tests/process_transfer_browser.cjs pilot/local-process-ui
```

Это необязательная dev-зависимость; основной запуск и CI используют только Python.
Тест проверяет обе группы/порядка, диапазон/незавершённый ввод, пропуски, четыре
полных и один частичный экспорт, отсутствие сетевых запросов и мобильного overflow.
Запускать в новой папке: существующие экспорты не перезаписываются. Скриншоты и
экспорты остаются локальными и всегда помечены `synthetic_test`.
