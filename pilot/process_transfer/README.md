# Исполнимый пилот 0.2: распределение работы и перенос ожиданий

**Технически проверяемый observer-пилот, не доказанный человеческий эффект.**
Участник читает вымышленный текст. Реальные LLM, голос, платные сервисы и скрытые
рассуждения не используются. Происхождение наблюдений нельзя менять задним числом.

Ревизия PR №4: теперь в обеих группах ассистент выполняет одну часть, модуль —
другую; случайно меняется распределение. Общий объём помощи и правильный итог
одинаковы. Будущая доступность модуля независимо задана. См. [протокол](PROTOCOL.md)
и [ответ на ревью](REVIEW_RESPONSE.md). Новизна проверена относительно переноса
доверия, приписывания способностей и credit assignment; мировое первенство не заявлено.

## Запуск

Python 3.12, стандартная библиотека. Из корня репозитория:

```bash
.venv/bin/python pilot/process_transfer/study.py build \
  --seed 20261105 --batch-id author-debug-v02 --output pilot/local-process-v02 \
  --role developer_pilot --origin human_observer \
  --study-info 'Авторская отладка. Файл остаётся у вас; можно не передавать или удалить. Внешний набор этим запуском не проводится.'
```

Получатся план, инструкция и **256 страниц-слотов**. Это полный комбинаторный
блок, не N и не уже существующие участники. Каждая последовательная четвёрка
балансирует распределение исполнителей × будущую доступность. При частичной
выдаче/отказах баланс не гарантирован.

Один человек — один неиспользованный слот. Выдавать слоты последовательно без
выбора человека под условие; случайный код и журнал назначения хранить отдельно.
Прерванный слот не переиспользуется. Не показывайте план/другие страницы заранее.
Автор, знающий гипотезу, остаётся developer_pilot; скрытие метаданных не делает
его внешним слепым участником.

Для внешнего сбора нужны реальные условия участия, контакт, хранение, удаление,
отзыв согласия и отдельный batch_id с role=volunteer. Это пока не организовано.
Два автора и технические тесты не образуют подтверждающую выборку.

## Техническая проверка

Для любой автоматизации явно используйте `--origin synthetic_test` и новую папку:

```bash
.venv/bin/python pilot/process_transfer/study.py build \
  --seed 20261105 --batch-id synthetic-v02 --origin synthetic_test \
  --study-info 'Только синтетическая техническая проверка.' \
  --output pilot/local-process-synthetic
.venv/bin/python -m unittest discover -s tests -p 'test_process_transfer*.py' -v
.venv/bin/python pilot/process_transfer/diagnostics.py
```

Диагностика выдаёт математические примеры, а не оценки людей. Она включает
ложноположительный сырой контраст и смесь глобальных сдвигов, способную создать
даже противоположные знаки по операциям. Отсутствие таких проблем в тестах не
означает идентификацию психологического механизма.

В этой ревизии реальный браузерный проход создал 8 полных и 1 частичный
synthetic_test экспорт и импортировал их; крайние ответы и пропуск сохранились.
Исходная форма 0.1 также пройдена и импортирована до изменения кода. Подробнее
о проверенном объёме и ограничениях — REVIEW_RESPONSE.md.

Дополнительный dev smoke test (Playwright/Chromium либо CHROME_PATH):

```bash
node tests/process_transfer_browser.cjs pilot/local-process-synthetic
```

Он требует новую папку без export-*.json и synthetic_test план. Это необязательная
зависимость, не часть Python CI. При отдельном запуске проверяет восемь сочетаний
и partial, desktop/mobile, сетевые обращения и JS ошибки. Наличие скрипта не
означает, что этот конкретный Chrome-прогон был выполнен здесь.

## Импорт

```bash
.venv/bin/python pilot/process_transfer/study.py analyze \
  --plan pilot/local-process-v02/plan.json \
  --exports /absolute/private/path/S001-P-0123456789ab.json \
  --output pilot/local-process-report-v02.json
```

Пропуски не заполняются. Проверки понимания описываются, но не исключают людей.
Отдельные ratings: умность, симпатия, полезность, трудность чтения и заслуга.
Четыре прогноза сохраняют абсолютную операцию и тему через неизменный план.
На available-пробах оценивается система с разрешённым модулем, без утверждения,
что она работает самостоятельно или обязательно успешно.

Отчёт разделяет роль/origin/measurement order/demonstration order/resources,
показывает абсолютные контрасты и coverage. Полный запланированный контраст — null
при неполном покрытии. Контрасты на общих доступных блоках помечены отдельно.
Missing-answer bounds — диапазоны возможных значений для полученных экспортов,
не доверительные интервалы и не оценка отсутствующих участников. P-values нет.

## Версии, данные и ограничения

0.2 меняет смысл условий и схему checks. План 0.1 не принимается как 0.2.
Старые данные читаются только сохранённой версией кода исходного PR №4
(be517c13ff8066422f2886c41b2c1b6c0f9f682c) в отдельной копии. Миграции смыслов нет;
не исправляйте хеши вручную. Точный JSON-хеш, происхождение и исходники связаны
с планом; изменение инструмента требует нового набора.

Обновление вкладки теряет несохранённые ответы; экспорт скачивается локально,
сам ничего не отправляет. Реальные планы, ответы, качественные комментарии и
отчёты не коммитятся. Только авторские стимулы/код/документы/синтетические тесты.
Код проверяет декларации происхождения, а не личность, согласие или независимость.
Статья со вторичным анализом не получает новых результатов из этого пилота.
