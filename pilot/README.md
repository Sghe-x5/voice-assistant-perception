# Человеческий пилот

1. Прочитайте [инструкцию](protocol.txt).
2. Откройте [форму](rating_form.html) локально в браузере.
3. Выполните [шесть сценариев](prompts_ru.txt) с двумя ассистентами.
4. После каждого диалога сохраните свои оценки, затем экспортируйте JSON.
5. Обработайте экспорт по [инструкции анализатора](analysis_readme.txt).

Форма хранит данные локально и ничего не отправляет. Ключ `scoring_key.json`
предназначен для разметки после субъективных оценок; не читайте его заранее.

Один человек с 12 диалогами — один участник, а не выборка из 12 людей.
Агентные прогоны не дают человеческих оценок. Реальные экспорты и транскрипты
не добавляются в Git и не смешиваются автоматически с опубликованными данными.

## Новый отдельный инструмент

[Пилот переноса ожиданий](process_transfer/README.md) использует вымышленные
текстовые сценарии и полный квадрат «тема × операция». Это наблюдательский
эксперимент с подготовленными стимулами, не живой голосовой диалог. Материалы и
технические проверки готовы; человеческих результатов пока нет.

## Сравнение моделей в диагностическом пилоте

Claude разрешён наравне с другими семействами. Чтобы охватить больше двух моделей,
подготовьте разные пары через [plan_comparison.py](plan_comparison.py); пример
конфигурации — [model_panel.example.json](model_panel.example.json). План содержит
только назначения, которые вручную переносятся в форму, а не наблюдения.
Полная инструкция и границы использования — в [плане исследования](../docs/research_plan_ru.md).
Старые фиксированные задания подходят для диагностического пилота; свободное
уточнение требует отдельного адаптивного сценария и протокола.
